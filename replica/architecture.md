# Architecture: Traccia, informed by the Plaud public-source recon

Date: 2026-11-15. Baseline: `ab2941b` on `sviluppo`, archive schema 6. Inputs: [recon](recon.md), [feature matrix](features.csv), existing application code. This document is a proposed incremental design. None of the new tables, routes or background behaviors below are implemented by adding this document. The feature matrix remains unverified, not a claim that existing Traccia features are absent.

## Implementation checkpoint — 2026-11-16

The first build now uses archive schema 7. Five extension tables are implemented: archive_identity, note_templates, subject_preferences, lecture_annotations and study_questions. Durable pipelines reuse existing study_jobs with checkpoint/provenance markers instead of duplicating the proposed processing tables. Import queues are explicitly session-local; transcript search is literal-token scanning rather than FTS5. Questions are independent source-bound requests rather than multi-turn threads. The SQL below remains a schema-6 planning artifact, **not** the current migration; application migrations in workspace.py/questions.py are authoritative. See build-log.md for implementation and qualification status.

## Stack and decisions

| Layer | Choice | Why |
| --- | --- | --- |
| Desktop | Existing pywebview/WebKit window, Apple Silicon | Preserve the native-window launch and current packaging; no second frontend. |
| Interface | Existing HTML/CSS/JavaScript and English/Italian catalogs | Extend current lecture/course views; original visual assets and wording. |
| API | Existing Python 3.11, FastAPI/Pydantic, Uvicorn | Reuse validated upload, authentication and job services. Dependency pins stay in requirements.txt. |
| Database | One SQLite database per archive, raw parameterized SQL | Existing data and backup compatibility; no ORM or cloud migration. |
| Search | SQLite FTS5 over immutable transcript segments | Local lexical retrieval before considering embeddings; rebuildable index with source anchors. |
| Models | Existing whisper.cpp, llama.cpp/Qwen and GTCRN through local workers | Local inference, explicit model installation, existing model hashes/licenses; no hosted fallback. |
| Audio | Existing minimal FFmpeg plus GTCRN; original and derivatives separate | Preserve playback and preview capabilities; default ASR on original/normalized input until listening/WER evidence supports changing it. |
| Files | Existing archive folders plus managed staging | Atomic rename, UUID filenames, checksums and backup inclusion; no object-storage service. |
| Jobs | Existing archive lease/worker, plus a durable orchestration state machine | One heavy model job at a time initially; no Redis, Celery, microservices or concurrent model loading assumptions. |
| Authorization | Existing bearer/cookie authentication; one trusted owner per archive | Explicit archive-scoped data-layer checks. Not multiuser authentication. |
| Server | Existing container for a single trusted user; i7 qualification pending | Same API/UI; no public multiuser deployment before isolation and authentication work. |
| Payments/email | None | Free local university workflow; no Stripe, email automation or commercial minute quota. |
| Hosting/sync | Localhost on Mac, optional user's server | No vendor cloud dependencies, no automatic external upload or Plaud connection. |

SQLite supports FTS5 ranking and external-content indexing; index/source consistency must be maintained explicitly ([official FTS5 documentation](https://www.sqlite.org/fts5.html)). Foreign keys must be enabled on **every connection**, with suitable parent/child indexes ([foreign-key documentation](https://www.sqlite.org/foreignkeys.html)). SQLite has no native `timestamptz`; use canonical UTC ISO-8601 text for new timestamps ([date/time documentation](https://www.sqlite.org/lang_datefunc.html)). These are deliberate adaptations of the skill's default Postgres schema conventions.

## Current versus proposed storage

Current seven domain tables remain: `subjects`, `lessons`, `audio_jobs`, `study_jobs`, `transcripts`, `notes`, `materials`. Recordings-in-progress and some derived results currently use sidecars; do not silently replace their formats. Current transcripts/notes are revision records with JSON content, not the normalized Plaud-like schema inferred in recon.

[Proposed SQL](schema.sql) adds **11 normal tables and one FTS5 virtual table**, excluding SQLite's internal FTS shadow tables. Combined domain total would be 18 normal tables plus that virtual index. This is extension DDL against schema 6, not a complete fresh database and not a runnable application migration. UUIDs are generated by Python and checked canonically at the API/data layer; SQL checks their length. No PostgreSQL-only UUID generation functions are used.

| New table | Purpose / ownership | Hard constraints and deletion |
| --- | --- | --- |
| archive_identity | One singleton UUID representing this archive's owner scope | Only one identity per archive; referenced ownership rows restrict deletion. Not a login/user table. |
| note_templates | Original academic prompt, name, revision, favorite | Unique name per archive; subject defaults restrict template deletion until reassigned. Existing generated notes retain configuration snapshots. |
| subject_preferences | Local defaults for one subject | One row per subject; optimistic revision, validated JSON, same-archive template reference; restrict subject deletion. |
| import_items | Staged upload, suggestions, confirmed metadata, batch grouping | One request key per archive, bounded size, terminal imported/duplicate must point to a lesson in the same subject. |
| lecture_annotations | Student highlight/text/image tied to original audio time | Valid nonnegative range; image material and lesson share subject; nonempty text; revision checks in API. Restrict source deletion. |
| processing_runs | Durable pipeline/configuration snapshot | One active run per lesson; unique request key; bounded state enum. |
| processing_steps | Ordered children linked to existing audio/study jobs | Unique position per run, at most one executor reference; cascade only when explicitly purging the parent run. |
| search_segments | Source text, immutable transcript/segment/time anchors | Unique transcript/segment; revision belongs to lesson and lesson to subject. Source rows pinned by citations cannot be deleted. |
| qa_threads | Conversation scoped to a subject or one of its lessons | Optional lesson must share subject; restrict deleting subject/source lecture. |
| qa_messages | Question/answer attempt with retrieval/model snapshot | One request key per thread; result state and nonempty final answer constraint; cascade on explicit thread purge. |
| qa_citations | Exact excerpt and source-segment reference | Unique ordinal, same archive as message/source; source deletion restricted. |

New owned rows carry `archive_id`; existing rows belong to the entire archive. Every authenticated query first binds the active archive, then checks subject/lesson/thread ancestry. Composite foreign keys enforce several relationships, while cross-thread/course citation membership, segment existence in transcript JSON, quote matching and time bounds are checked in the data layer. Archive scope is not a substitute for future tenant identity: do not present this as multiuser-ready RLS.

All new tables have `id`, `created_at`, `updated_at`. New times are UTC with `Z`; existing `+00:00` timestamps are parsed semantically and are not rewritten. The application updates `updated_at` in the same transaction as a mutation. Lecture calendar dates stay date-only, not midnight timestamps. Audio offsets are integer milliseconds from the original recording, not wall-clock times. Indexes cover foreign keys and stated list/filter orders. The schema intentionally contains no money columns.

### Migration and archive invariants

1. Before production integration, allocate the next archive schema version after checking the current release; do not assume schema 7 is still free. The current app must refuse the future version. `schema.sql` intentionally does not alter `user_version`.
2. Hold the existing exclusive archive lease before migrations, validate current schema, create a verified closed-archive backup, check free disk space, and run extension DDL transactionally. SQL never downloads models or starts jobs.
3. Create one archive UUID, backfill only derived search data, run foreign-key/integrity checks, then update `user_version` last. On error roll back; an old binary must not operate on the new archive. Downgrade uses the prior backup, not destructive reverse SQL.
4. Extend backup/restore and archive reconciliation for every new table and staging/context artifact. Keep interrupted restored work cancelled until explicitly restarted, as in the existing restore policy. Migrations and indexing do not change original audio, raw transcripts or accepted manual chapter text.
5. FTS is rebuildable; cited `search_segments` rows are provenance records and cannot simply be dropped during reindex. Index all immutable revisions; normal search filters to the requested/current revision snapshot. Historical Q&A keeps its old source anchors.
6. Transcript text and user materials remain outside Git. No production archive is touched during architecture validation.

## API contracts by recon flow

All paths below are under `/api/v1`. **E** = existing route inspected in the application; **P** = proposed. Existing request/response contracts remain authoritative in code. “A” = authenticated owner of the active archive; “A+S/L/T” additionally checks subject/lesson/thread membership. UUID syntax alone is never authorization. Proposed statuses: 201 created, 202 queued, 409 stale revision/conflicting request, 413 too large, 422 invalid configuration, 404 out-of-scope resource. Never return credentials, filesystem paths or raw model command lines.

API inventory: **73 unique method/path contracts** in the flow tables: 46 existing, 27 proposed. Repeated use across flows is counted once; health/bootstrap/static assets and ancillary existing endpoints are outside this scoped inventory.

### F01 — Import (S01,S02,S05)

| Method path | State | Caller | Input → output |
| --- | --- | --- | --- |
| POST /audio/preview | E | A | file → metadata suggestions; this is import metadata, not denoising preview |
| POST /subjects/{subject_id}/lessons | E | A+S | confirmed multipart file/metadata → lesson or duplicate conflict |
| POST /import-items | P | A+S | file, subject_id, batch_id, request key → staged item/suggestions; no AI processing yet |
| GET /import-items | P | A | batch_id, limit, cursor → item statuses; omit local source paths |
| PATCH /import-items/{item_id} | P | A+S | confirmed title/teacher/date/subject, base revision → editable ready item |
| POST /import-items/{item_id}/commit | P | A+S | request key → imported/existing lesson; exact retry reuses result |
| DELETE /import-items/{item_id} | P | A+S | uncommitted item → cancelled; remove staged copy only |

One request per file, shared batch UUID; no second batch table or bulk multipart transaction. Initial concurrency limit: two upload streams, one decoder. Close the import dialog without cancelling work; explicitly label a cancellation. Changing confirmed subject changes target dedup scope and revalidates membership.

### F02 — Record (S03,S04,S05)

| Method path | State | Caller | Input → output |
| --- | --- | --- | --- |
| GET /recordings | E | A | none → recoverable recording drafts |
| POST /recordings | E | A+S | subject/title/date → local PCM draft |
| POST /recordings/{identifier}/chunks | E | A+L | sequence, PCM bytes → durable acknowledged sequence |
| POST /recordings/{identifier}/finish | E | A+L | draft ID → saved or already-saved lesson |

No browser-to-Plaud handoff. To support markers while recording, extend the **existing draft journal** with sequence-based annotations; checkpoint metadata atomically with acknowledged PCM. On finish, map sample count to milliseconds and promote markers to `lecture_annotations` transactionally/idempotently after lesson creation. If interrupted, recovery resumes promotion by stable marker UUID. Do not pretend a draft already has a lesson foreign key.

### F06 — Find and ask (S07,S10)

| Method path | State | Caller | Input → output |
| --- | --- | --- | --- |
| GET /subjects/{subject_id}/search | P | A+S | bounded text query, optional lesson, cursor → revision/segment/time/snippet anchors |
| POST /subjects/{subject_id}/qa-threads | P | A+S | title, optional member lesson → thread |
| GET /subjects/{subject_id}/qa-threads | P | A+S | cursor → thread list |
| GET /qa-threads/{thread_id} | P | A+T | cursor → scoped messages and citations |
| POST /qa-threads/{thread_id}/messages | P | A+T | question, request key → queued answer attempt |
| GET /qa-messages/{message_id} | P | A+T | ID → state, answer, source anchors or abstention |

| POST /qa-messages/{message_id}/save-note | P | A+T | target course/base revision, request key → notes proposal, not accepted text |

First search uses escaped tokens/phrases and subject-filtered FTS/BM25 with excerpts. Never interpolate raw SQL or expose an unrestricted FTS expression parser. Freeze current transcript IDs when question starts. Initial bounded retrieval: up to 12 source segments, adjacent context as budget permits, max 12,000 source characters, max 4,000-character question; these are starting caps, not quality claims. Do not include earlier AI answers as primary evidence.

Retrieve → optional lexical reranking → local Qwen answer in structured claim/citation form → deterministic membership/quote/number validation → render source links. Unsupported or missing evidence yields abstention/uncertainty; matching a quote does not prove an entailment. Prompt injection in recordings, PDF text or template data cannot activate tools, network or code. Conversation context may help resolve references, but evidence is freshly retrieved within the same scope. Course-wide Q&A follows single-lecture evaluation, including negative questions and specialist terminology.

## Failure modes, access and resource limits

- **Time zones/DST:** display UTC timestamps in the selected local zone, retain imported date provenance/confidence, never invent a year or teacher from a filename. Sample offsets survive timezone changes.
- **Idempotency:** client UUID per mutation; exact retry returns prior result, changed payload under same key gives 409. Store canonical request hash in the relevant snapshot. Lesson dedup remains `(subject_id, sha256)`; identical bytes can intentionally exist in different courses.
- **Races:** archive file lease plus transactions; partial unique active-run index; atomically claim each step. API optimistic revisions protect preferences, annotations, transcript and notes. Course-wide notes generation waits behind accepted-revision changes rather than overwriting them.
- **Crash recovery:** separate staging from originals; fsync/checkpoint capture; atomic file rename then recoverable database commit. Recover filesystem/DB split failures by stable UUID/hash; never report imported until a lesson exists. Cancel is a request until executor termination is acknowledged. Parent run cancellation does not delete results.
- **Model/resource limits:** no automatic downloads; queue unavailable-model work as blocked with clear install action, not endless retries. One heavy ASR/LLM/denoising task at a time initially. M4 24 GB and i7 24 GB need measured memory/time budgets; no speed promises from RAM alone. CPU server performance remains unmeasured.
- **File limits:** retain current 512 MiB audio upload limit, 20 MiB images and bounded PDF worker (50 MiB/200 pages); don't copy Plaud's limits. Validate content/decoder, bound memory/time, sanitize filenames, no following external symlinks, and reserve disk before staging/derivatives.
- **Search consistency:** FTS insert/update/delete triggers and transactionally written source rows; rebuild only FTS after validation. Old source rows remain pinned by historical citations. Corrected transcripts immediately become the default search scope. A literal number match is necessary for some checks, never sufficient for medical/scientific correctness.
- **Offline/realtime:** no websocket required; bounded polling with backoff and page/lesson request guards. Internet needed only for explicitly requested initial model downloads/updates. Close/reopen must recover durable jobs. Server recording requires browser microphone support and a secure context; remote HTTP is not assumed equivalent to localhost.
- **Multi-tenancy:** current auth admits one trusted archive owner; do not expose multiple users to one archive. Later stage requires real sessions, per-user isolated archive resolution and ownership checks for every query/file/job, CSRF/TLS and revocation. No `archive_id` selected by an untrusted request.
- **Privacy/deletion:** keep audio, text, user prompts and answers out of logs/Git; backups contain sensitive content too. Explicit archive erasure must cover originals, staging, derivatives, search and historical snapshots, with backup-retention disclosure. No claim of GDPR certification or instant removal from external backups. Never remove source records while accepted notes/citations depend on them without an explicit reconciliation policy.
- **Packaging/licensing:** maintain GPL-3.0-or-later project license and third-party notices/source obligations. New schema requires matching application/backup versions. Signing/notarization and clean-Mac verification remain separate release gates, not solved by this architecture.

## Architecture validation (not feature acceptance)

The proposed DDL was executed against a disposable database created by the current application, with seven baseline tables and `user_version=6`. Checked: 11 new normal tables plus one FTS virtual table, foreign-key/integrity checks, singleton archive identity, active-run uniqueness, rejection of negative timestamps and cross-subject annotations, and FTS insert/update/delete consistency. All passed; schema version remained 6. This validates the SQL proposal only, not migration recovery, source-grounded Q&A or route implementation. No personal archive or lecture was used.
